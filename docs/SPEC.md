# NightCat 功能规格（定稿）

版本：2026-09-16 · 状态：已定稿，未开工

---

## 1. 定位

控制这台 Mac 什么时候可以睡、什么时候不许睡。三档递进的「保持唤醒」+ 防忘记关的安全网。

不做的事：不管理屏幕亮度、不做风扇控制、不做定时开关机、不做跨设备同步。

## 2. 三档定义

| 档 | 语义 | 实现 | 需 root | 屏幕 |
|---|---|---|---|---|
| **屏幕常亮** | 屏幕不熄灭，方便看盘/演示 | `caffeinate -d` | 否 | 常亮 |
| **防空闲** | 系统不因空闲睡眠，屏幕可灭 | `caffeinate -i -m -s` | 否 | 可灭 |
| **合盖不睡** | 合上盖子继续跑 | `pmset -a disablesleep 1` | **是** | 合盖即灭 |

**递进语义**：选高档自动包含低档。UI 上是一个分段控件，不是三个独立开关。

**实现分层**（重要）：

| 档 | 实现在哪 | 为什么 |
|---|---|---|
| 屏幕常亮 | App 层自己起 `caffeinate` 子进程 | 不需要 root |
| 防空闲 | App 层自己起 `caffeinate` 子进程 | 不需要 root |
| 合盖不睡 | 走特权 helper 翻 `disablesleep` | 需要 root |

也就是说：屏幕档和防空闲档是纯 App 层逻辑，**不动 helper**；只有合盖档用到现成的 helper / XPC 通道。

> `disablesleep=1` 是全局禁止睡眠，空闲也不会睡，所以合盖档不需要再叠 `caffeinate`。

**生命周期差异**（决定 UI 要讲什么）：

- 屏幕档 / 防空闲档：App 进程活着才有效，App 崩了自动失效 → 安全
- 合盖档：写进系统状态，App 退出依然生效 → **危险，忘关就耗电发热**

合盖档的危险性决定了这个 App 有一半功能其实是"防止你自己忘关"。

## 4. 菜单栏图标规则

图标本体是一个笔记本图形，状态靠**颜色**表达，倒计时只在必要时出现。

| 档位 | 图标颜色 | 倒计时 | 锁定标 |
|---|---|---|---|
| 关闭 | 灰 | 不显示 | 若有 |
| 屏幕常亮 | 蓝 | 仅设了定时器时 | 若有 |
| 防空闲 | 青 | 仅设了定时器时 | 若有 |
| 合盖不睡 | 橙 | **强制显示**（无定时器时显示"持续"） | 若有 |

- 合盖档强制显示文字是刻意的——这一档最该被看见。
- 锁定标放在**图标的右下角**，用小锁形状，不要用颜色编码（颜色已经被档位占满）。
- 讨论稿里用过的参考色（dark mode，未最终确认）：灰 `#B4B2A9`、蓝 `#85B7EB`、青 `#5DCAA5`、橙 `#EF9F27`。
- 被否掉的方案：加状态圆点。它与颜色是同一个信息通道，属冗余，不做。

## 5. 面板与交互

- **单击菜单栏图标 = 打开面板**（不是直接切换档位）。
- 面板内包含：档位分段控件、定时器、电池/电源状态、helper 状态、设置入口。
- 面板的具体布局**尚未出设计稿**，需要先出 HTML 稿确认再实现。

## 6. 档位锁定

锁定的是**档位**，不是开关——关闭也算切档，同样拦。

| 环节 | 行为 |
|---|---|
| 触发 | 面板状态行右侧的小锁按钮，点亮即锁定当前档 |
| 锁定后 UI | 分段控件置灰不可点；菜单栏图标右下角出现锁标 |
| 尝试切档 | 二次确认：「档位已锁定。切到「防空闲」会中断正在运行的任务。」→ **[切换并解除锁定]** / [取消] |
| 自动锁定 | 可选开关「定时器启动时自动锁定」，跑批场景用 |
| 持久化 | **不跨重启保留**，重启后解锁 |

存在意义：批处理正在跑时误点切换会中断任务。

## 7. 定时

- 预设：15 / 30 / 60 / 120 分钟 + 自定义。
- **到点直接关闭全部档位，不逐级回落**（行为可预测）。
- 上游已有 `Sources/Shared/AutoOff.swift`（15 分钟–4 小时）可改造，但它的语义是 on/off，需要改成档位语义。

## 8. 电池与安全

**核心原则：电池下不静默降级，提示后由用户决定。**

面板内联警示条（不用系统弹窗），文案方向：

> 当前使用电池。合盖不睡约每小时耗电 8–12%，且合盖散热受限。
> **[继续]**　[改用防空闲]　[取消]

| 规则 | 行为 |
|---|---|
| 电池下开启合盖档 | 弹上述提示，用户决定 |
| 记住选择 | **默认不记住**，每次问；提供「本次会话不再提醒」（活到重启） |
| 电量低于阈值（默认 20%） | 直接拒绝，不给「继续」按钮 |
| 运行时拔掉电源 | 触发同一提示流程，**不静默降级** |
| 过热 | 暂停保持唤醒（上游 `SafetySettings.swift` 已有热保护逻辑，复用） |
| 仅插电时保持 | 复用上游「only-while-charging」设置 |

## 9. 退出恢复与外部接管

- App / helper 退出时，把 `disablesleep` 还原到**接手前的值**（不要无脑写 0）。
- **必须能识别「外部接管」**：Amphetamine 或其他工具开的 `disablesleep` 不能显示成自己开的。
  上游 `Sources/Shared/StateReconciler.swift`（196 行）已有状态对账机制，在此基础上扩展。
- 检测到外部工具在管电源时，界面明确显示「当前由 XXX 控制」。

## 10. 明确不做（已砍，别再提）

| 项 | 理由 |
|---|---|
| **CLI** | 与系统自带 `caffeinate` 重叠约 90%，唯一增量是"把合盖档绑到命令生命周期"，当前用不上 |
| **URL Scheme** | 价值在 Shortcuts / Raycast / Alfred 触发，暂无需求 |
| **Sparkle 自动更新** | 更新源指向上游，必须拆除；自带 appcast 暂无必要 |
| 状态点图标方案 | 与颜色编码冗余 |
